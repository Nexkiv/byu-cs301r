**Assistant**: The industry standard is defined by PEP 8. For variable names in Python:

- Use snake_case: all lowercase with words separated by underscores.
  - good: my_variable, total_count, user_name
  - bad: myVariable, TotalCount, userName

- Constants (values that don’t change) use ALL_CAPS with underscores.
  - GOOD: MAX_SIZE, DEFAULT_TIMEOUT

- Classes use CapitalizedWords (CamelCase), but that’s for class names, not variables.
  - good: class UserProfile

- Private vs public (within modules/classes):
  - Single leading underscore for weak “private” use: _internal_value
  - Double leading underscores triggers name mangling in classes: __private_value (usually not for general use)

- Prefer descriptive names; avoid single-letter names except in very small, well-known loops (e.g., for i in range(n)).

- Line length: aim to keep lines under 79 characters (some teams extend to 88).

- Tools: linters/formatters like flake8 (style, naming), and Black (formatting) can help enforce the conventions, though Black focuses on formatting, not naming.

Quick examples:
- Variable: user_age, total_amount, max_retries
- Constant: DEFAULT_TIMEOUT, API_ENDPOINT
- Private: _cache, __init__ (special method)
